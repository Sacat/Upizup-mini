# Combat

## MINI-190 pistol handling for every humanoid (2026-10-02)

Researched and built a procedural pistol handling system on the Humanoid IK pass: two-hand grip fitted to each rig's arm length, torso and head aim, pistol finger curls, spring recoil, draw/holster, low ready and a full magazine-change reload, driven by an `IPistolUser` (the real `FirearmController` for Sacat and Franki, `NpcPistolUser` for any NPC). Works on rigs with 30 finger bones and on fingerless low-poly NPC hands. Play Mode renders for Sacat, Franki and a town NPC are in `Logs/Tasks/MINI-190/Renders`. Gameplay values, the scene and NPC behaviour were not changed; no live NPC carries a gun yet. Feel with the real camera is unreviewed. Details, sources and lessons: `Docs/WorkPackets/MINI-190.md`.

## MINI-188 online-referenced hand fit (2026-10-02)

Online manufacturer and Unity references showed that MINI-187's zero-error finger-joint alignment alone was a weak proof of hand fit. A named upper `BackstrapAnchor` now complements the model's `GripAnchor` and `ShotOrigin`. The runtime root moves 25% toward the thumb-index web solution while keeping the handle within the curled fingers in both sampled character renders. Saved-scene checks measured web-proxy distances falling from 35.6 to 26.7 mm (Sacat) and 38.7 to 29.0 mm (Franki), with grip-to-middle-joint gaps under 10 mm. A full web alignment looked worse because the available clip is not a pistol-specific finger pose. No gameplay ray or damage changes. Windows build passed; live aim motion remains unreviewed. Details and reference links: `Docs/WorkPackets/MINI-188.md`.

## MINI-187 grip and muzzle anchors (2026-10-02)

The Lalay Tool now has explicit `GripAnchor` and `ShotOrigin` transforms under its visual root. ## MINI-186 visual asset and reusable prop workflow (2026-10-02)

The modern Lalay Tool was generated from the project's ImageGen concept using one Hi3D v3.0 Quality Geometry + Stylized Texture attempt (65 credits). The 1.99-million-triangle raw FBX and 8192 texture were measured and reduced in Blender to a 2,998-triangle, one-component, manifold mesh with a 1024 texture and 0.19 m length. Both player objects now reference that model instead of the three primitive cubes; gameplay raycasts and ammo rules are unchanged. The project resolved Unity's Standard shader, so the color texture and tint must be assigned through `_MainTex` and `_Color`. Exact asset process, measurement JSON, three-angle renders, in-engine rest-pose render, scene verification and Windows build evidence are in `Docs/WorkPackets/MINI-186.md` and `Tools/ArtPreview/Mini186Source/`. ## Architecture

- `Assets/UpIzUpMini/Scripts/Combat/MeleeMoveLibrary.cs` - the data table. `BaseChain` (private) is the 4 shared punches; `GetChainFor(characterName)` appends the right per-character kick and is the ONLY way `SimpleMeleeCombat` should read the chain. Each `ComboMove` carries id, clip, damage, windup/active/recovery timing, reach/radius/arc/bodyRadiusBonus. Adding a new shared combo step means one more `BaseChain` entry; a new PER-CHARACTER step (like the kick) means a new id/clip pair plus a branch in `GetChainFor`.
- `Assets/UpIzUpMini/Scripts/Combat/SimpleMeleeCombat.cs` - the driver. Tracks `_comboStep` (advances one per landed Attack press, wraps after the chain length, resets to 0 if the player doesn't follow up within `comboResetSeconds`). Reads everything else (damage, timing, contact geometry) from the current `ComboMove`.
- `Assets/UpIzUpMini/Scripts/Combat/MeleeContactResolver.cs` - shared geometry: `MeleeAttackProfile` (per-move reach/radius/arc/bodyRadiusBonus data) and `IsInsideForwardContact`/`TryFindNearest` (the actual hit-test). Used by the player, `PoliceOfficer`, `FactionBrawler`, and `CompanionCombatAssist` - each can carry its own profile values.
- `Assets/UpIzUpMini/Scripts/Combat/NpcRagdoll.cs` - generic ragdoll wrapper (works on any Humanoid Animator, not Sacat-specific despite reusing `SacatRagdollBuilder`). `Ragdoll(impactVelocity)` goes dynamic with a one-time velocity match; `Recover()` reverses it.
- `Assets/UpIzUpMini/Scripts/Combat/NpcCombatHealth.cs` - MINI-038's health/hit-reaction/knockdown system, extended in MINI-119 to branch on whether an `NpcRagdoll` is present. With one: every hit ragdolls; fatal hits lie `fatalLieSeconds` (3s) then fade; non-fatal hits lie `nonFatalLieSeconds` (2s) then recover and resume walking. Without one (shopkeepers/dealers/mission NPCs - none currently get an `NpcRagdoll`): falls back to the original animation-only hit-reaction/knockdown behaviour, unchanged.
- Shared Animator Controller: `Assets/UpIzUpMini/Art/Animations/StarterAssetsThirdPerson.controller`. Every combo move's clip is baked as a state on this ONE shared controller (all characters use it) via `HumanoidAnimationLayerBuilder.EnsureActionLayers`, driven by `Mini011PhaseBSetup.GetSharedActionEntries()`. **This is the actual thing that plays at runtime** - see the "what didn't work" entry below before assuming a clip swap took effect.
- Animation source: real Mixamo motion capture, the user's own free account (`Docs/ASSET-REGISTER.md` MINI-AST-122/123/124), not the previously-owned Kevin Iglesias "Human Melee Animations FREE" pack (that pack has zero unarmed clips - every "Attack" entry in it is a weapon swing).

## What worked / what didn't
- **2026-09-07 MINI-143:** a full-body kick animation does NOT stop PlayerController input. Add a move-data kick flag, run combat before locomotion, and suppress planar input/residual speed/turn/jump during that swing while retaining gravity. Sampled real clip foot extension peaks at0.794s Sacat (1.5x state) /0.680s Franki; old0.22s damage was premature. New active windows0.68–0.90 /0.57–0.79, totals1.60/1.75s; optional PlayAction duration override aligns fade with effective kick playback without touching other actions or Animator assets. AdvanceContactWindow preserves NPC once-only Advance API, but player retries a miss until active-window end and latches the first hit. Test exact damage once, late entry, lock release, held virtual input, wall/behind/range rejection. Real feel still awaits user playtest; no bone-contact or new animation system claimed.

- **(2026-08-31) Stationary sellers had no physical hit body (MINI-135).** Police were hittable because their patrol setup already adds a CharacterController; non-patrolling shop sellers only had a visual and `TownNPCInteractable`, so no collision could reach `VehicleImpactResponder`. `TownNPCInteractable.Awake` now idempotently ensures the same lightweight CharacterController dimensions used by walking NPCs. Trigger and collision contacts share `TryApplyImpact`, which lazily adds protected combat health/ragdoll and preserves `RecoverAndReturnToPost`. A CharacterController—not a standalone CapsuleCollider—is deliberate so `NpcRagdoll` disables/restores it during knockdown.

- **(2026-08-30) Ragdoll recovery should be settle-aware, and crash momentum must be capped (MINI-134).** `NpcRagdoll.IsSettled` exposes bone-speed state without owning timing. `NpcCombatHealth` adds a small severity-based lie delay, waits up to 1.25 seconds more for physics to settle, then root-aligns every nonfatal recovery to the landed hips before animation resumes. Vehicle momentum transfer is reduced to 50%, capped at 11 m/s with only 1.8 m/s of lift, and the closest-bone impulse is capped at 2.4 m/s. This keeps hits readable without the earlier excessive launch. Player crash recovery reuses the same generic humanoid ragdoll but is intentionally separate from player health/death.


- **(2026-08-30) Vehicle damage must enter through the same health endpoint as melee (MINI-132).** `VehicleImpactResponder` converts real `Collision.relativeVelocity` and contact position into speed-scaled damage plus one shared momentum vector, then calls `NpcCombatHealth.HitFromImpact`. This avoids a second vehicle-only health system. Franki's Strong trait now multiplies every move (1.25 damage / 1.30 impact), not only his final kick. Police and gang attacks now read separate three-step sequences from `NpcCombatMoveLibrary`; their 8–13 damage moves and longer windup/recovery keep them visibly weaker/slower than either protagonist.
- **(2026-08-30) Ragdoll recovery needs role policy and root alignment (MINI-132).** Sellers/named contacts cannot use the ambient fatal-despawn branch. Their role resolves to `RecoverAndReturnToPost`: after two seconds the root is ground-aligned to the fallen hips, animation resumes, health resets, and the CharacterController walks to the exact start pose. Villagers/police fade and return after 100 seconds; unclassified Dog Life members retain `ExternalPool`, preserving MINI-130. Original non-unit character scales are cached/restored instead of forcing `Vector3.one`.

- **(2026-08-30) Pooled inactive NPCs cannot trust references cached only by `Awake` (MINI-130).** The built-player stack showed `NpcCombatHealth.ResetForRespawn` throwing repeatedly while Dog Life members were eligible to return, preventing `RivalGangSpawner` from ever reaching `SetActive(true)`. `ResetForRespawn` now refreshes its controller, animation manager, ragdoll and renderer array from the live hierarchy and null-checks replaced renderer entries. The focused test deliberately clears the renderer cache before reactivation and now passes.

- **(2026-08-29) A move's `fullBody` flag matters even when `PlayAction` reports success.** After fixing the missing-ActionEntry bug, the log showed `played=True` for the kick, yet the user still didn't see it. Cause: the kick was set `fullBody=false`, so it played on the "Action" layer - which `BuildUpperBodyMask()` deliberately masks to exclude `LeftLeg`/`RightLeg`/foot IK (so a punch can play while the character keeps walking). A kick's whole point is leg movement; masked out, the state fires but nothing visibly happens. Fixed by setting `fullBody=true` so it plays on the unmasked `FullBodyOverride` layer instead (same layer vehicle seating already uses). Lesson: `played=True`/`HasState=True` only proves the STATE exists and was entered - it says nothing about whether the relevant BODY PARTS are actually unmasked for that layer. Check the mask, not just the boolean, for anything below the waist.
- **(2026-08-29) The forced-reimport theory was WRONG - re-tested and it did not fix anything.** The real cause, found by reading `HumanoidAnimationManager.PlayAction`'s source line by line instead of re-guessing: it gates on its OWN per-character `_byId` dictionary (`RebuildLookup()`, built at `Awake()` from the SERIALIZED `actions` list) BEFORE it ever calls `Animator.HasState` - so `Mini120DiagnoseHasState.cs`'s check (which called `Animator.HasState` directly, bypassing `_byId` entirely) was checking a completely different, unaffected code path and could never have found this. The actual bug: `Mini120PatchPunchClip.cs` (the very first fix, earlier this session) only REPLACED the existing "Melee" entry's clip in each character's `actions` array - it never ADDED entries for the new "MeleeHook"/"MeleeRightHook"/"MeleeFinisher" ids, because those didn't exist yet when that tool was written. Every character's saved `actions` list still had only the one "Melee" entry, so `_byId.TryGetValue` failed immediately for the other three. Fixed by `Mini120AddComboActionEntries.cs`, which specifically ADDS the missing rows (not replace) to all 23 characters that already carry the jab (69 new entries total, confirmed by exact count). **Lesson for next time**: when a `PlayAction`-style call silently fails, read the ENTIRE method's early-return chain in order before assuming which gate is the problem - `HasState` was the most visible/obvious check but not the first one actually executed.
- **(2026-08-29) Reading the user's real `Player.log` directly from disk was far faster than asking them to paste it.** Standalone builds write to `%USERPROFILE%\AppData\LocalLow\<CompanyName>\<ProductName>\Player.log` (company/product name from `ProjectSettings/ProjectSettings.asset`) - on the same machine running the build, this is directly readable, and is the single most reliable way to diagnose a "doesn't work in the real build" report on this project (same lesson as several `Vehicles.md` entries, formalized here for reuse).
- **(2026-08-29) Fixing a clip only on `HumanoidAnimationManager.actions` did NOT work.** That per-character serialized data is only read for `clip.length` (blend-out timing) and `Animator.HasState` existence checks - `Animator.CrossFadeInFixedTime(id, ...)` actually plays a STATE BY NAME/HASH on the shared `StarterAssetsThirdPerson.controller` asset, and that state's baked `Motion` is a completely separate thing that the scene-side ActionEntry patch never touches. **What worked**: call `HumanoidAnimationLayerBuilder.EnsureActionLayers(controller, GetSharedActionEntries())` again directly against the real controller asset - `EnsureState`'s own documented behaviour re-authors an existing state's Motion in place. Confirmed via direct before/after read of the state's `.motion.name`, not assumed. See `Mini120PatchAnimatorController.cs`.
- **(2026-08-29) The "warped punch" root cause was a missing animation, not a tunable bug.** The already-owned free pack had zero bare-fist clips; the game was reusing a one-handed WEAPON-swing clip (`HumanM@Attack1H01_R.fbx`) for punching with no weapon in hand. Confirmed visually via `Mini120RenderPunchPose.cs` (renders a character posed by a clip via `AnimationClip.SampleAnimation`, no Play Mode needed) - the old clip visibly rotated the whole torso sideways mid-swing (a sword follow-through).
- **(2026-08-29) A free, hand-keyframed Asset Store animation pack ("Fighter Pack Bundle FREE") looked cartoonish** - user's own words, "looks weird, like cartoon movements." Real motion capture (Mixamo, free with an account) looked correct on the first try. Lesson: for combat/character animation specifically, prefer real mocap sources over generic free packs even when both are free.
- **(2026-08-29) The over-generous hit detection root cause, measured not guessed**: a hardcoded `+0.35f` "body radius" forgiveness bonus in `MeleeContactResolver.IsInsideForwardContact`, stacked on a `reach=1.65` tuned for a lunging weapon swing, registered hits up to 2.3m away and 0.6m to either side. Exposed as `MeleeAttackProfile.bodyRadiusBonus` (a real field, optional constructor param defaulting to the old 0.35f so `PoliceOfficer`/`FactionBrawler`/`CompanionCombatAssist` keep their existing feel unless explicitly retuned). New combo moves use ~0.15 and reach 0.95-1.05 - re-measured max reach 1.3-1.4m.
- **(2026-08-29) Verifying multi-press combo cycling via Editor batch mode did NOT work** - `UnityEngine.Time.time` does not advance outside Play mode, so a scripted second `Attack()` call is blocked forever by the real cooldown gate (`Time.time < nextHit`). The combo-advance arithmetic itself (`(step+1) % length`) was verified structurally; the actual in-game multi-press behaviour needed the user's real hands-on test.
- **Not yet tried**: trimming a long raw Mixamo clip (e.g. a punch clip padded with several seconds of idle/bounce before the actual strike) via `ModelImporter.clipAnimations` frame ranges. Came up while investigating "Hook.fbx" (turned out to actually be a boxing idle loop per rendered sampling, though the user separately confirmed watching a real hook strike in Mixamo's own preview when downloading manually - worth resolving which is true before adding more moves from raw Mixamo downloads without the user watching each one first).
