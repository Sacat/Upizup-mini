## Architecture

- `Assets/UpIzUpMini/Scripts/Vehicles/VehicleRider.cs` / `VehicleSeat.cs` (MINI-066) - the shared rider/seat system every two-wheeled vehicle uses. `VehicleRider` handles seated/wheelie pose blending and Humanoid IK; `VehicleSeat` carries PER-VEHICLE baked `seatedOffset`/`seatedPitch`/`wheelieOffset`/`wheeliePitch` (not hardcoded on `VehicleRider` itself, since that's shared across every bike).
- `Assets/UpIzUpMini/Scripts/Vehicles/SuperMotoVehicleInteractable.cs` - the SuperMoto's mount/dismount/pillion interactable, the reference implementation for a vehicle with its own independent input/physics (no throttle/steer relay needed).
- `Assets/UpIzUpMini/Scripts/Vehicles/SuperMotoHandFootLock.cs` - direct bone-override hand/foot IK (`Gadd420.IK`, not Mecanim's built-in `OnAnimatorIK`, which failed twice on this project). Retries every frame until `animator.isHuman` is true, to survive the auto-mount-at-spawn timing race.
- `Assets/UpIzUpMini/Scripts/Vehicles/BikeRiderAnimation.cs` - `UpdateWheelieOverlay(bool)` blends in an authored wheelie pose on the `FullBodyBlend` layer, on top of the position/pitch blend (which alone only translates the body, never reshapes the arms). `WheelieClipWeight` (public property) controls how strongly that authored pose applies - dialed down per-vehicle at Mount() time if needed (see ledger below).
- `Assets/UpIzUpMini/Scripts/Vehicles/VehicleSpawnController.cs` - purchase/spawn/dev-test scaffolding for every vehicle. `WireSuperMotoInstance(instance, player, spawnPos, autoMount)` is the extracted, shared wiring block both the dev spawn path and the real Car Dealer "koss" purchase branch call - written once, not duplicated.
- NPC ragdoll on the vendor's own SuperMoto rider (crash physics) inspired the pattern reused for `Combat.md`'s `NpcRagdoll` - see that file for the actual NPC-combat version.

## What worked / what didn't

- **(2026-09-04) A prefab's serialized `KeyCode` beats the C# field default - check both when remapping input (MINI-140).** The requested "E to mount, Q to wheelie" scheme needed changes in three places, not one: (1) the C# `[SerializeField]` defaults on `BikeInteractable`/`SuperMotoVehicleInteractable`/`CarInteractable`; (2) `TMAX_560.prefab` and `RangeRover_Vehicle.prefab`, which serialize their own `wheelieKey`/`dismountKey`/`mountKey` / `enterKey`/`exitKey` ints and override the code default (an input-binding-only prefab edit - no mesh/transform/seat/effect value touched; `101`/`102`/`113` = `KeyCode.E`/`F`/`Q`); (3) `SuperMotoWheelieKeyRemap.GetLeanBackValue()`, a vendor `Input_Manager` override that read `KeyCode.E`/`KeyCode.Q` directly - E removed, Q kept. The runtime-`AddComponent`ed SuperMoto interactable + wheelie remap need no prefab edit. E routes through the normal `InteractionDetector`/`GameAction.Interact` path plus each vehicle's own wider mount-range key check (kept, so the bike's ~4.25 m mount reach survives; `InteractionDetector`'s 2.75 m prompt range is unchanged). Mount now records `_mountedFrame`/`_enteredFrame` so the same E key-down cannot be re-read as a dismount later that frame (script execution order between `InteractionDetector` and the interactable is not fixed). Q also calls the partner on the phone (`CellPhoneController`) - that path is now gated on `PlayerController.IsControlled` (false while mounted; `VehicleRider.Mount` and `CarInteractable.Enter` both clear it), so a Q tap mid-wheelie doesn't summon anyone; on foot the call is unchanged. F is no longer read by any vehicle and stays the melee Attack key; the now-inert `BikeInteractable.ConsumedMountKeyThisFrame` melee guard was left in place (always false, harmless). Focused MINI-140 + standing MINI-065/139/137 regressions, Windows build and 15 s smoke pass; control feel is hands-on and still needs the user's ride test.
- **(2026-09-01) A wheelie speed gate must apply to sustain as well as start (MINI-139).** The TMAX previously required a minimum speed only to lift; once `WheelieForcingPose` became true, `canSustain` ignored speed so the front stayed raised near a stop. The effective start/sustain floor is now 12 mph (19.31 km/h). Falling below it routes through the existing zero target and current `wheelieRiseRate`, giving a smooth lowering rather than a snap. Rear-wheel grounded state remains absent from sustain because an earlier measured test proved contact chatter can freeze deep wheelies. Focused and standing crash regression plus Windows build/smoke pass; live feel remains.
- **(2026-08-31) Collision-relative velocity is not enough during a forced wheelie (MINI-138).** The kinematic-style lift can give the tail/rear body a large reported relative contact speed while real road speed is low. During an active wheelie (>8 degrees), ejection now requires both a 1.15x harder contact and actual Rigidbody speed at/above the normal 16.5 m/s hard-crash floor. This blocks the user's easy low-speed wheelie ejections while retaining genuine high-speed wall ejection. Upright collision behavior and every wheelie/visual setting remain unchanged. Focused regression and Windows build/smoke pass; live feel remains.- **(2026-08-31) Reuse the complete proven SuperMoto lift behavior per vehicle, not as a permanent character change (MINI-137).** The TMAX now caches the active rider's `WheelieClipWeight`, applies the in-game SuperMoto's proven 0.22 authored lift blend while mounted, then restores the prior value on dismount. Existing TMAX seat keyframes, hand IK, pillion and handling remain untouched. TMAX exhaust is smaller, capped at 24 particles, at most 22% opaque and roughly half as frequent. Rear-underside sparks are a separate mobile-bounded system (20 particles) gated by rider present + 88.75/89-degree cap + at least 12 mph. Focused and standing wheelie regressions plus Windows build pass; live visual acceptance remains.

- **(2026-08-31) Wheelie limits and crash detection must remain separate (MINI-136).** The user superseded the earlier 90/95 fall-back rule: both TMAX and SuperMoto now use a shared hard 89-degree commanded-wheelie ceiling, including runtime clamping so prefab/debug values cannot bypass it. Bike tilt alone never ejects or kicks the bike backward; only MINI-135's filtered hard physical collision path can eject driver/pillion. This touched no steering, suspension, wheels, rider fit, spawn or scene data. Focused and standing impact validation plus Windows build/smoke pass; wheelie feel still needs live play.
- **(2026-08-31) Raw collision magnitude was too eager for bike ejection (MINI-135).** The MINI-134 11.5 m/s magnitude test could treat road landings, bumps and glancing contacts as hard crashes. The corrected path ignores upward-facing ground contacts, measures only closing speed along the contact normal, raises hard-obstacle ejection to 16.5 m/s, and requires 24.75 m/s when the contacted object is an NPC. The explicit wheelie contract is now 90 degrees balanced, mounted through 95 degrees, then a backward angular kick plus shared driver/pillion ejection beyond 95. Scene placement, handling, wheels, rider fit and suspension remain untouched.

- **(2026-08-30) Separate crash observation from approved vehicle handling (MINI-134).** `BikeCrashEjectionController` reads only Rigidbody collision speed and bike tilt. It does not touch steering, suspension, wheel mapping, rider fit or the tuned wheelie motion. TMAX and SuperMoto expose the same `CrashEject` bridge, which first uses their proven dismount cleanup and then hands driver/pillion to `PlayerCrashRagdoll`. Hard solid impacts use an 11.5 m/s gate; NPC hits require 1.35x that speed so ordinary pedestrian contact does not constantly throw the rider. A tilt beyond 92 degrees while moving triggers the same path. `VehicleDamageController` adds shared 100-point durability to bikes/cars and rights a disabled vehicle after four seconds with partial health. Focused thresholds and both public bridges are validated; real crash feel still needs playtest.

- **(2026-08-30) A merged car body can gain convincing wheel motion without a destructive Blender edit (MINI-133).** The cleaned Range Rover source is one `geometry_0` mesh, so its original wheels cannot be isolated in Unity. The reversible solution overlays four fitted SuperMoto-reference tyre meshes at the existing WheelCollider hubs, adds five cheap dark-metal spokes per wheel so spin reads, and drives each pivot with `WheelCollider.GetWorldPose`. Mapping is explicit by axle/side; only the already-steered front colliders turn. The old fused wheels remain underneath, exactly like the accepted TMAX overlay limitation. Rear marks/smoke reuse approved Motorbike Physics Tool art and are bounded to actual braking/slip; exhaust is a separate right-rear outlet. Do not rerun `Mini071RoverVehiclePrep.BuildVehicle`, because that broad builder would overwrite later prefab work; use the additive MINI-133 setup instead.


- **(2026-08-30) One impact adapter can cover every vehicle without retuning handling (MINI-132).** `VehicleImpactResponder.Ensure` is attached by TMAX, SuperMoto and car interactables. It observes collision data only; it never writes steering, suspension, wheel, seat or mass values. Below 3.5 m/s it ignores contact, then scales 12–100 health damage up to 18 m/s, transfers bounded vehicle momentum to the shared NPC ragdoll, and applies a per-target cooldown so multi-collider vehicles cannot damage the same NPC repeatedly in one strike. Shop NPCs are upgraded lazily at first impact, so the approved live scene did not need regeneration.

- **The "ghost Animator" bug (the single biggest root cause of the whole MINI-119 SuperMoto saga)**: `VehicleRider` had `[RequireComponent(typeof(Animator))]` plus a same-object-only `GetComponent<Animator>()`. Sacat's real Animator lives on a child (`Visual`), not the root - Unity silently auto-created a second, permanently blank Animator on the root, and every hand-IK attempt (Mecanim `OnAnimatorIK`, then a direct bone-override) was talking to the dead ghost. This was misdiagnosed as "Editor batch-mode can't bind an Avatar" FOUR separate times before being properly root-caused from the user's own live Inspector check, not batch tooling. **Prevention**: never assume the Animator is on the same object a script is attached to; use `GetComponentInChildren<Animator>()` and never declare `[RequireComponent(typeof(Animator))]` on a script that might land on an object that doesn't directly carry one.
- **Ragdoll physics and a runtime-built Animation Rigging graph (RigBuilder/TwoBoneIKConstraint) were both tried for hand/foot tracking and abandoned** after recurring, hard-to-reproduce failures - `VehicleRider`/`VehicleSeat` (the proven MINI-066 system) is what actually worked.
- **Mecanim's built-in `OnAnimatorIK` hand IK failed twice** on this exact character/bike despite IK Pass genuinely being enabled. A continuous direct bone-override (`Gadd420.IK`, the vendor's own technique) is what actually works reliably - runs in `LateUpdate`, after the Animator, can't silently under-apply the way Mecanim IK did.
- **(2026-08-28) Patching only `HumanoidAnimationManager.actions`-style per-character data does NOT change what plays** - same lesson as `Combat.md`'s ledger, applies here too since both systems share the same underlying `HumanoidAnimationManager`/shared-controller architecture.
- **(2026-08-28) Wheelie back-clip fix: measured before touching numbers.** User reported "the back goes through the handlebar." `Mini119WheelieBackClipCheck.cs` simulated the seated-vs-wheelie position/pitch math directly and found the chest actually moves AWAY from the handlebar during a wheelie by that math (0.62m -> 0.99m) - the position/pitch numbers were NOT the cause. The real cause was `BikeRiderAnimation`'s authored wheelie-overlay clip (tuned against the TMAX's handlebar geometry, not the SuperMoto's). Fix: dial `WheelieClipWeight` down (0.45 -> 0.22) while mounted on the SuperMoto specifically, cached/restored on Mount()/Dismount() since that component lives on the shared player object (also used by the TMAX) - can't be a permanent change.
- **(2026-08-28) Pillion boarding as a one-shot check at Mount() time did NOT work with auto-mount.** The original TMAX pattern (`BikeInteractable.BoardPillion`) only works because the player always walks up and presses F first, giving the passenger time to catch up. An instantly-auto-mounted bike breaks that assumption. Fixed by checking every `Update()` instead of once at Mount() time.
- **(2026-08-24) Two torque-based attempts at a continuous roll-corrector (`SuperMotoUprightAssist`) were built and rejected after real testing** - one resonated into a violent tumble, one was too weak and let the lean creep. Replaced with a kinematic `MoveRotation`-based approach (same technique already proven for the wheelie) - no torque, no gain to tune, cannot resonate.
- **A self-reinforcing stuck-pitch bug**: measuring pitch via `Mathf.Asin(forward.y)` (fold-back-prone past 90deg) and baking that measurement directly into the real rotation every frame turned one bad reading into a permanent stuck pose. Fixed by using a signed angle around the flattened-forward-derived right axis instead.
- **Real Editor batch-mode verification repeatedly disagreed with actual gameplay** across this whole task (the `Input_Manager` destroy-order bug and a world-axis `FreezeRotationZ` constraint bug were both invisible to batch tests, only found from the user's own `Player.log` or direct play feedback). Batch-mode checks are still valuable for catching what they CAN catch (see the many `Mini119*.cs` tools), but a final "works in real gameplay" sign-off from the user remains necessary before calling a vehicle feature done.

A validator forcibly displaced both wheels over 250 cycles and each returned to the same hub point.
- **(2026-08-30) Rider lean was compounded, not one animation alone (MINI-131).** The TMAX combined cosmetic bike roll, 81% procedural rider follow, a 15-degree rider ceiling, and a sustained authored lean clip. - **(2026-08-30) Empty physics vehicles can disappear before the player reaches them (MINI-128).** The TMAX was spawning correctly but could roll away on Lalay. `BikeInteractable` now applies its parking brake, zeros velocity and holds the rigidbody kinematic while empty; mounting releases the lock and wakes the body. - **(2026-08-30) Reuse proven effect art through a vehicle-specific adapter, with a strict mobile budget (MINI-128).** `TmaxRoadEffects` reuses the installed SuperMoto skid-trail and smoke prefabs but reads the TMAX's own WheelColliders. - **(2026-08-30) Pillion correction should preserve approved placement and change only orientation/pose (MINI-128).** The TMAX passenger height/offset `(0.11, -0.01, 0.32)` was already approved.
